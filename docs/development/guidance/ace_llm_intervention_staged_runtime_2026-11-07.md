# CPU qualification of a copied runtime

The two retained import probes do not identify an import-order correction. The first timed out before reaching SciPy, and the second ran with a different order and a potentially warmer shared filesystem cache. The next qualification keeps the original import sequence and makes preparation explicit.

The proposed CPU job copies the existing `/projects/paco0228/miniconda3/envs/ace` runtime into an uncompressed archive, then stages it on the allocated node's `$SLURM_SCRATCH`. No package is installed, downloaded or upgraded. Files are captured with byte hashes and before/after identity checks. Symlink targets are preserved, with absolute, escaping and special objects rejected. Directory set-group-ID bits are recorded but omitted on the private copy. No original file or permission is changed. At most 100,000 objects and 16 GiB of file contents are admitted. Partial output remains on failure.

The archive manifest binds exact member order, kinds, modes, content hashes and links. The stage operation checks the independent manifest and archive pins before creating the destination, then checks each extracted object's contents. It does not call tar's general extraction API. This provides a coherent captured copy of the enumerated bytes, not a claim that the shared source is atomically frozen or that its entire dependency graph is self-contained. Trusted caller-owned output directories are required. Malicious same-user or root modification is outside this interface's protection.

The fresh copied interpreter then runs the unchanged original import probe once. Its model/source/runtime authentication and import ordering are preserved. A caller hook captures loaded module paths and `/proc/self/maps` before allowing the original successful receipt. The wrapper rejects imports or native mappings from the old runtime and installed modules outside the staged prefix. Platform libraries remain external and visible in the maps. The copied interpreter must adopt the staged prefix. This is observed path evidence, not universal dynamic dependency closure.

The original-sequence child must return successfully within 180 seconds measured by its parent, with a separate 185-second outer kill bound. The original diagnostic's 210-second alarm is still in its unchanged source, but cannot relax the shorter caller limit. Owned process-group cleanup must complete even when the leader returns. A successful wrapper also requires the expected worker receipt and origin record. No model weights, training, scientific world or environment response is used. CPU import success does not qualify the actual GPU model service.

Proposed resources are one CPU, 3 GiB and 30 minutes on `ucb736_asc2`, `acpu/cpu-normal`, with zero GPUs and no requeue. The 1,740-second supervisor alarm leaves a scheduler cleanup margin. Full source traversal, hashing, archive writing and staging have not been measured for this runtime. The bounded CPU allocation measures that work before any GPU request. It requests the smallest CPU count and preserves failure instead of automatically increasing the limit. The 180-second service startup target is not extended.

At proposal time the cycle has 4,763 closed allocated CPU-seconds and 836 GPU-slice-seconds. Including the cumulative 3,600 preparation allowance and the proposed 1,800-second cap gives 10,163 of 57,600 CPU-seconds. No new GPU reservation is proposed. These admission values are separate from process CPU and elapsed measurements. Source, packet and caller review, fresh journal/queue reconciliation, both controller locks, remote pins and scratch readiness are required before submission. This document is not evidence of execution.

The helper's initial six artificial file methods had five passes and one macOS path-alias failure. Canonicalizing the existing output parent corrected `/var` versus `/private/var` resolution. Only the affected roundtrip method was rerun, and it passed. Independent review then found two issues. Directory traversal now raises on enumeration errors, and link containment is checked after the entire link graph exists. Two new regressions passed, and the separate recheck closes both findings. All three attempts are preserved. No actual environment was copied by these fixtures.

The caller's three initial fabricated methods passed. Its independent review identified that startup-receipt I/O could extend the child timeout. The correction arms a real timer before process creation and receipt writing, uses the remaining absolute deadline for waiting, and restores only the remaining original supervisor allowance after bounded group cleanup. A child is not started with fewer than 200 seconds of preparation time left. Two new fabricated methods check delayed receipt I/O and insufficient remaining time. They passed without rerunning the original methods. All preparation receipts exclude unmetered implementation and review overhead. Failure-path origin enrichment was optional and remains deferred. A failed import still retains its original phase, stack, stderr and failure evidence.

If the staged sequence qualifies, preparation and extraction costs still have to be included in the design of a later GPU service attempt. Staging on a CPU node does not persist onto a different GPU node. The archive can be reused, but the later job must explicitly budget and measure its node-local extraction and verification before model loading. No unmeasured speedup or causal diagnosis is asserted.
