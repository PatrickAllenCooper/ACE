## BLOCKING: the budget-fairness experiment has not been run

**This is the single open item that determines whether the paper's headline
claim is defensible. Everything else in this document is secondary until
this runs.**

What is missing, precisely: every number currently in
`paper/iclr_ace_2027/paper.tex` Table 1 (and the 30-node table) uses
episode-matched accounting -- ACE and the five baselines each run for N
episodes, and the table reports final loss at that episode count. This is
exactly the comparison 4 of 5 NeurIPS reviewers correctly objected to,
because ACE's episodes are not equivalent in oracle cost to the baselines'
episodes (Appendix `app:budget-extended`: ACE ~4-5x, Max-Variance ~65x,
Bayesian OED ~500x samples, Random/Round-Robin/PPO 1x, oracle queries per
decision). We have never run the corrected version of this table. The
`--query_budget` flag and `--lookahead_on_student` mode exist, are
unit-tested, and are described in the paper -- but the actual experiment
that uses them to produce a fair Table 1 has not been executed anywhere,
including on CURC.

**What the missing experiment is, concretely:**
1. Pick a shared total-oracle-query budget (aggregate it from a completed
   run's `query_budget.json` via `scripts/analysis/aggregate_query_budget.py`,
   or use a round number, e.g. matched to ACE's typical 171-episode x ~4.1x
   multiplier total).
2. Run ACE under `--lookahead_on_student` (1x multiplier, so its
   episode-budget and query-budget are the same number) AND under normal
   env-based lookahead with `--query_budget` set to the shared total.
3. Run all five baselines with `--query_budget` set to the same shared
   total, so each gets as many episodes as its own multiplier allows within
   that budget (e.g. Random gets ~4-5x more episodes than ACE at the same
   query cost; Bayesian OED gets ~1/500th as many).
4. Compare final/best MSE across all methods at matched total queries. This
   is Table 1's actual replacement.
5. Job scripts already written for this: `jobs/curc_submit_5node_budget_fairness.sh`,
   `jobs/curc_submit_5node_budget_fairness_baselines.sh` (5-node);
   `jobs/curc_submit_30node_budget_fairness.sh`,
   `jobs/curc_submit_30node_budget_fairness_baselines.sh` (30-node).

**Why it matters / what depends on it:** the paper (Section "Budget
Accounting" and the Limitations section) explicitly states this comparison
is queued, not reported, and commits to treating either outcome as
informative rather than picking one and hiding the other:
  - If ACE wins under total-query-matched accounting: the paper keeps a dual
    strong claim (wins on both episode-count and query-count accounting).
  - If ACE does not win under total-query-matched accounting: the
    `--lookahead_on_student` variant (1x multiplier, honest by construction)
    becomes the headline configuration instead, and the env-lookahead
    variant is reported as a higher-oracle-cost alternative rather than the
    main result.
Until this runs, the paper is making an accounting-transparency claim
("here is the true cost of every method") without the accompanying
fairness claim ("and ACE still wins once you correct for it") -- these are
different claims, and only the first one currently has evidence behind it.
**Do not let a future session or a paper draft conflate the two.**

## ICLR 2027 Resubmission - In Progress

**Prior venue:** NeurIPS 2026 submission received critical reviews (4 of 5
reviewers flagged the same core issue: environment-query budget accounting
did not count lookahead probes, only executed interventions, making the
episode-count comparisons in Table 1 an apples-to-oranges comparison against
baselines that do not use lookahead). One reviewer (d6tT) also asked whether
DPO specifically was necessary, versus simpler preference-based updates.

**Decision:** Resubmit to ICLR 2027 rather than patch the NeurIPS version.
Reframe the paper's central claim around the LM-prior + lookahead-selection
mechanism (already the more defensible finding, per the anonymization and
ACE-w/o-DPO-tied-at-30-nodes results in the NeurIPS Section 5.2), with DPO
recast as one of several viable calibration layers rather than the headline
contribution. See the resubmission plan for full reasoning; do not edit the
plan file itself.

### Status by phase

**Phase 1 (code instrumentation): DONE**
- `--query counter`: every `env.generate()` call in `ExperimentExecutor` is
  now tagged (`executed`, `lookahead`, `observational`, `candidate_probe`)
  and logged per episode.
- `--lookahead_on_student`: scores the K candidates using the student's own
  forward pass instead of fresh oracle samples, so executed-interventions-only
  accounting is honest under this mode (zero additional oracle queries for
  lookahead).
- `--query_budget`: stops a run once cumulative environment samples hit a
  target, enabling total-query-matched comparisons across methods with very
  different per-decision oracle costs.
- `--policy_update {dpo, sft_best, ranking}`: SFT-on-best-candidate and a
  pairwise Bradley-Terry ranking loss (no reference-policy KL term) as
  DPO alternatives, reusing the existing candidate/lookahead machinery.
- Unit tests added for all four items (`tests/`).
- `baselines.py` audited for oracle-query multipliers: Max-Variance ~65x per
  decision (`n_candidates=64` probe generations), the 5-node Bayesian OED
  baseline in `run_reviewer_experiments.py` ~500x samples / 1001x calls per
  decision (`n_candidate_values=10` x `n_mc_samples=20` per one of 5 nodes),
  Random/Round-Robin/PPO at 1x (no candidate probing), ACE at 4-5x under
  env-based lookahead (K=4 candidates + 1 executed) and 1x under
  `--lookahead_on_student`. This audit is now Appendix "Budget Accounting:
