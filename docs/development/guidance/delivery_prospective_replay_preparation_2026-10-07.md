## Acceptance and runtime gates

`accepted_before_scores` checks the frozen registration, complete matrix counts,
fit-seal binding, successful audit-supervisor status/account/resource limits and
acceptance hash before projecting metadata. A strict JSON scanner skips both
scientific analysis objects without decoding their numbers or strings. The
projection binds the original digest and requires the full original field set,
eighty training and forty evaluation receipt maps, three phase hashes, all640
replay discrepancy entries, timing and predeclared tolerance. Malformed hashes,
nonfinite/negative/boolean telemetry and noninteger exit codes are rejected.
The failure flag is checked before any acceptance access. It validates the full original
640-checkpoint acceptance, runtime, response count, source and score/complete/seal
bindings. It never opens the score or prediction arrays. The eventual full replay
must then independently verify every declared raw input/model/attempt binding
and recompute all outcomes; upstream acceptance alone is insufficient.

`runtime_gate` requires torch2.9.1, NumPy2.2.6, SciPy1.15.3, pandas2.3.3,
SymPy1.14.0 and PyYAML6.0.3. The local A/C environment deliberately fails this
gate. No dependency installation, new allocation or silent version substitution
is authorized by preparation. A bounded runtime/replay execution after the
original acceptance must fit the remaining existing CPU allowance and receive
an explicit source/input/resource freeze before submission.
