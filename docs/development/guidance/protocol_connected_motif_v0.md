# Connected interaction-motif simulator gate (implementation draft)

Created 26 September 2026 after the disjoint-motif screen. This is a simulator contract, **not a frozen confirmation protocol or result**. `scripts/research/connected_motif.py` builds a known DAG with k interaction children, each later motif taking the previous child and a new root as parents. Extra nodes form a linear descendant chain after the final motif, so all N nodes belong to one connected component. Every natural motif output is a noisy `a*x1 + b*x2 + c*x1*x2` mechanism. Intervening on a prior child replaces its structural equation; that child is marked ineligible as a training label for the acquired batch. The smoke check asserts the graph, dimensions, intervention values, masking, and finite outputs.

Before any CURC submission, implement a common persistent acquisition harness for five controls: random and balanced-coverage singles, random and balanced-coverage pairs, and posterior-risk pairs. All must receive the same observed graph, parent contexts, child mask, batch size, update rule, and sealed test service. The posterior-risk selector may simulate *candidate contexts using the learner*, but it must never use truth coefficients or held-out labels. A pair targeted at downstream motif j may destroy an upstream training label; both selection score and actual posterior update must account for that. Log every selected action, all acquired samples, actuator uses, masked labels, cost, and final post-update non-root/feasible-intervention error.

Development: 3 seeds, N=15 with k=1/3, root SD 0/.15, λ=0/4, fixed cost budget 400. Promotion to a modest CURC development run requires receipt validation and policy parity on those cells. Next, compare N=15/30/100 at fixed k=3, then k=1/3/10 at fixed N=30 (where feasible). N=300 stays gated. Extra descendant padding should not automatically degrade local motif estimation; measure full-graph error separately to avoid a trivial scale claim. Freeze fresh system seeds, primary metric, acquisition budget, and multiplicity treatment only after the local pilot is sound.

No Azure or other closed-source model calls are part of this phase. The current code supplies the simulator and action menu only; it does not yet choose actions, train a learner, or produce outcome claims.
