# Open-model partial-identification development protocol

Status: task/evaluator specification. No model inference has been run. This is a small synthetic capability screen, not an external scientific benchmark.

Generate 20 tasks with seeds 2100–2119. Each has two binary SCM candidates with `U~Bernoulli(p)`, `X=U`, and deterministic `Y=f(X,U)`. Draw `p` from {1/4,1/2,3/4}; draw a common observational diagonal `f(0,0), f(1,1)`; draw different off-diagonal entries for the two candidates. Verify exactly that the observational `(X,Y)` laws coincide and that at least one `do(X)` action changes the response law. Ten task menus offer `do(X=0)`, `do(X=1)`, and an irrelevant `do(Z=1)`; ten offer only the irrelevant action. Costs are equal. Randomize candidate order by seed. These are independently sampled tables within one narrow task family, not 20 independent causal domains.

Stage 1 prompt gives both candidate truth tables, the observational law, a uniform prior on the two candidates, the legal action menu, and an explicit two-candidate scope. Require: the candidate-set interval for `E[Y|do(X=1)]`, whether observations identify the candidate, and a legal action maximizing expected information gain or an explicit abstention if the menu cannot distinguish them. Grade with exact enumeration. Tie-break legal actions in displayed order. `do(Z=1)` has no effect on X or Y.

Stage 2 is separate to prevent answer leakage into action choice. It reveals one reference intervention and one binary outcome sampled from a randomly selected candidate and U. Require the posterior probabilities of the two candidates and an updated candidate-set statement. Score posterior log loss against the exact likelihood update; never use another LM to grade the answer. A zero-probability observation under both candidates is invalid and must be excluded by generation.

Controls: exact-enumeration tool, a fixed rule parser on the same supplied tables, direct open-model response, and open model with access to the exact tool. Freeze prompts, parsing, model checkpoint, generation parameters, and scorer before model inference. Report action accuracy, false certainty/abstention, interval validity, posterior error, invalid JSON, time, and GPU allocation. This development family is too simple for an originality claim; a positive signal requires a different independently authored task family and misleading-semantic variants. No Azure or closed-source call.

Use local exact generation first. If the fixture passes consistency and receipt/replay validation, a small capped open-model run on CURC is justified. Select one version-pinned locally available open checkpoint and a short GPU job, with explicit `ucb736_asc1` account, output root, source revision, job ID, and complete receipt. Do not launch while the scheduler is unhealthy or while the task/evaluator contract is incomplete.
