## Current position and the actual blocker

The original ACE paper's broad superiority claim did not survive metric, learner, and budget correction. The reproducible SCM harness and result custody are useful, but they are infrastructure rather than a new effect.

The strongest positive result is **numerical and conditional**: posterior-risk selection of two-node interventions beat the same-menu fixed factorial-hub design on fresh binary-tree systems (mean feasible MSE .02694 versus .03972) and on a later, separately frozen random-recursive family (.02270 versus .05918). The fresh fanout gate failed (.01327 versus .01535; interval crosses zero). These are sequentially chosen synthetic families, all using the same motif equations and learner. No foundation model contributed to those gains. Another seed grid on these generators cannot establish transfer.

The other paths have stop signals. Wrong semantic proposals still harmed the numerical prior; BoxingGym Lotka supplied no advantage beyond a data-only family selector, and the Signal wrong-source-count gate accepted the false cue on all three reused worlds. Modular repair improved an already-known nonlinear motif but harmed unchanged motifs: the latest whole-action-block screen raised unchanged error by 8.8%–21.8%, exceeding the 5% protection limit in every stratum. PEV had mixed fresh controls and no distinctive integrated-variance advantage. The hand-written action parser went 8/8 on its in-sample fixture and 0/8 on a later stress fixture. An offline Qwen2.5-1.5B direct partial-identification canary failed all eight frozen JSON responses; the exact arithmetic control already scores 20/20 on that finite suite.

The blocker is **experimental discrimination**, not queue access. We need a task on which a stronger simple control can lose, a model can add a distinct capability, and the evaluation cannot be won by fitting to our previous synthetic motifs. CURC is available; spending more GPU time before that task is specified would not solve the scientific problem.

## Primary question for the next phase

Can a validated action interface and an uncertainty-aware numerical controller choose informative, affordable interventions in a **new scientific system**, under a shared learner and held-out interventional prediction target? Treat the two contributions separately:

1. Given the *same formal legal menu*, does a numerical controller improve held-out prediction over a strong fixed varied-value schedule, coverage, and random design at the same realized cost?
2. Given only an independently written description, does an open model compile a better legal menu than a frozen rule/template parser, with zero invalid actions executed? Give both controllers the resulting menu when measuring downstream value.

An external success on question 1 would support acquisition transfer, **not** a foundation-model contribution. A compiler success on question 2 would support language grounding, **not** better causal inference. Combining them is a later factorial experiment if both component gates pass.

## Parallel investigations and stop gates

### Lane B: external action-design feasibility — lead lane

**Candidate:** [CausalMan](https://github.com/boschresearch/CausalMan) at source revision `17529dad5ec8b8c691494c617b9af4533aa44bf8`. It is an independently authored manufacturing SCM with hard interventions, partially observed outputs, and micro/small variants. The repository documents interventions through a dictionary; its source currently appears to generate roughly 14,000 internal samples per batch before returning a requested subset. It bundles about 7.6 GB of configurations and uses AGPL-3.0. These are feasibility concerns, not a selected benchmark or a performance claim. [Causal Chambers](https://www.causalchamber.ai/) is a fallback source of physical intervention data, but its available legal joint actions and repeatability need an audit. BoxingGym Signal's coordinate queries and NeuronBench's dynamic protocol choices are valuable external tasks but do not directly replicate our two-node known-graph intervention problem.

**Next deliverable:** complete the source/API and data-license audit, followed by at most one **CPU-only** CURC `micro` custody smoke if the API supports two legal simultaneous interventions on observable causes. Initial pinned-source inspection found that `sample()` returns **six** objects (including a fully observed private dataset and DAG), whereas the README quick start shows four; a solver must receive only the selected public data. The FCM accepts multiple intervention keys, but converts string-valued intervention expressions with `eval`; pass **validated numeric values only**, never raw model text. The `apply_interventions()` method is a stub that clears the dictionary, so use a verified direct API path in the smoke. Pin source and dependency hashes; use ACE scratch, not the full `/projects` checkout. Measure setup time, generated versus returned rows, peak host RAM, wall time per action, graph/parameter stability across calls, action legality, intervention mask, and the ability to keep private test responses out of the policy process. Preserve an exact query ledger and source revision. No GPU is justified. Stop this candidate if small actions require unbounded full-batch generation, paired interventions are not valid, or a public-only learner cannot be evaluated without exposing hidden state. Do not force the old Gaussian-linear risk score onto this partially observed nonlinear system.

**If feasible:** freeze one prediction target, action costs, legal one/two-actuator menu, equal-budget acquired data, and a learner that all policies share. First compare fixed factorial/varied-value, matched random, and graph-aware coverage. Add a predictive-uncertainty controller only after the learner's held-out predictions and uncertainty calibration pass a same-data screen. A fresh confirmation requires at least 20 independently parameterized systems or an equivalent independent-world unit; **audit whether CausalMan seeds change the physical model or only the sampled noise** before treating seeds as independent systems. Repeated queries on one simulator instance do not count as independent systems. Require at least 20% lower primary error than the best same-menu simple control, with a paired interval excluding zero. Report runtime and host memory as well as acquired responses. A failed external result is retained, not replaced silently by another favorable task.

**Source audit completed at the 2 October 00:28 UTC heartbeat:** [verified source findings](../../../results/local_causalman_source_audit_20261001/README.md). The micro subtree is about 145 MB. Seeds vary sampling, while the high-level call mixes fixed batch/path configurations, returns only the last graph, and makes observable-column selection partly action-dependent. Do not submit a multi-seed confirmation through that API. Next inspect one pinned batch/path with the unchanged lower-level sampler and measure a bounded local engineering probe before a CPU custody submission. Public target eligibility, ranges, schema, runtime, memory and response-count checks remain open; static source verification does not satisfy them.

### Lane D: action-language compilation — lead lane in parallel

Freeze the existing rule parser, validator, typed output schema, and a simple template baseline. Obtain at least 20 **independently authored** constraint descriptions from public experimental documentation or a collaborator who does not see the answer generator or parser failures. Include cost caps, forbidden combinations, indirect actuators, and no-legal-action cases. An adjudicator writes the formal schema and gold legal menu **before** model calls; source/provenance and ambiguous cases are recorded. The existing 8/8 and 0/8 hand-written fixtures remain development only.

First perform a CPU-only fixture/scorer audit: exact-menu recall, false legal actions, abstention, and deterministically validated downstream action value. If the baseline has headroom and descriptions are genuinely independent, freeze the prompt and run one small offline open-model canary on CURC. Cache raw responses; the validator rejects malformed and illegal proposals before any environment query. Compare strict parsed output rather than forgiving post-hoc extraction. Advance only if the open model improves *reachable useful actions* over the strongest parser and executes zero invalid actions. Record tokens, GPU memory/utilization, active compute time, and model revision. A site-minimum one-GPU allocation must have a measured startup limit and a short wall cap; perform parsing and fixture preparation on CPU first.

The local intake/scorer is `scripts/research/action_language_external_gate.py`. Its JSONL fixture rows require `id`, `description`, `provenance` (`author`, `source`, `authored_at`, `gold_adjudicator`), `schema`, and a complete `gold_actions` enumeration; the author and gold adjudicator must differ. This metadata is a custody check, **not proof of independence**: record the actual source and adjudication separately before accepting the 20-task gate. Optional proposal rows have exactly `id` and `actions`; the scorer reports invalid proposals, duplicates, false legal actions, recall, abstention, and exact menus. It does not execute any action or call a model. Existing internally authored fixtures may test the scorer with a one-task minimum, but cannot satisfy the independent 20-description gate.

The [source intake](action_language_source_intake_2026-10-01.md) now identifies three official Opentrons documents as one external source group, with zero adjudicated tasks. State, adjacency, compatibility, and exception constraints require a richer formal representation before scoring. Pin the sources and audit that representation; do not convert agent-written paraphrases into purportedly independent tasks.

### Lane A: fallible semantic priors — one bounded diagnostic

On saved public data, compare broad/data-only, correct-cue, wrong-cue, and an **abstaining** candidate-family selector with exactly the same learner and fits. The development target is to avoid the wrong-cue harm; do not use the three scored BoxingGym worlds as confirmation. If an acquired-data-only gate cannot keep wrong-cue error within 5% of the broad baseline while retaining a benefit for correct cues, stop this lane for now. If it can, freeze fresh worlds and independently written metadata before another open-model proposal. Distinguish familiar-law recall from transferable semantics.

### Lane C: modular repair — one bounded redesign, then stop or promote

The next repair rule must explicitly compare **in-support and shifted action strata** and may abstain to the source-warm or scratch predictor. Freeze it before a new system set; no more tuning of thresholds on the 12 exposed fanout systems. The development requirement is changed-motif improvement **and** at most 5% unchanged-motif degradation in every source-size/policy stratum against the strongest same-data simple control. If a single bounded CPU redesign fails, pause C rather than building a neural adapter. Only after fresh protection and at least 2× target-query savings over scratch/retrieval should a measured one-GPU prototype be considered.

### PEV and partial identification — retained controls

Do not run another same-generator PEV seed sweep. The endpoint-coverage, naive-variance, and random-DAG outcomes remain controls; a new PEV test needs a genuinely different graph generator and a reason the score differs from naive variance. Keep the exact 20-task partial-identification suite as a calibration and refusal diagnostic. Its 20/20 arithmetic baseline is an accuracy ceiling, so a model cannot demonstrate a performance gain on that suite. A broader partial-identification study needs a harder candidate space and a separately specified benefit (for example reduced computation or useful proposal coverage) before another GPU call.
