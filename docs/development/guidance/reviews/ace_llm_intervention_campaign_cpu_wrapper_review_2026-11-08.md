## Required finding

### P1 — Preserve the screen CLI's binary stdin and nonzero return status

**Wrapper anchor:** [lines 457–460](/Users/pat/code/ACE/scripts/research/prepare_llm_intervention_campaign_cpu.py:457), with the resulting success publication at [line 469](/Users/pat/code/ACE/scripts/research/prepare_llm_intervention_campaign_cpu.py:469).

`numeric_child` replaces `sys.stdin` with `io.StringIO(public)` and directly calls the selected module's `main()`. For every `--numeric-entry screen` invocation, the accepted [screen CLI reads `sys.stdin.buffer`](/Users/pat/code/ACE/scripts/research/llm_intervention_screen_policy.py:172). `StringIO` has no `buffer`, so the first read raises `AttributeError` before the policy can inspect the public envelope or choose an action. This affects `uniform_random`, `menu_coverage`, `local_information`, and `target_risk` in both artificial worlds. It is an interface defect in the new wrapper, not in the accepted CLI.

The [screen CLI's error handler](/Users/pat/code/ACE/scripts/research/llm_intervention_screen_policy.py:182) catches that ordinary exception, prints a rejected diagnostic to stderr, and **returns 2**. The wrapper discards this return value. Provided the following runtime check succeeds, it writes a numeric `terminal.json` claiming `status='complete'`, forwards empty stdout, and exits successfully. The campaign then fails when its charged executor tries to parse that empty completion. Thus the packet can incur numerical training and initial responses before failing, while the numerical call's own terminal incorrectly claims completion. A genuine future CLI rejection would suffer the same return-status problem even after the stdin mismatch is corrected.

**Required correction:** supply a bounded in-memory stdin object that supports the accepted text and `.buffer` interfaces, while preserving the captured public input bytes. Honor the called CLI's result before publishing a successful numeric terminal or forwarding a completion. The screen CLI returns `0`/`2`; the existing [ranker CLI](/Users/pat/code/ACE/scripts/research/llm_intervention_policy_cli.py:14) returns `None` on normal completion and raises on error. Handle those actual contracts explicitly, retaining captured output and failure evidence on rejection. Do not change the accepted CLI or numerical selection logic.

The new [numeric-prefix/tail test](/Users/pat/code/ACE/scripts/research/test_prepare_llm_intervention_campaign_cpu.py:148) checks arguments, and the [saved-join fixture](/Users/pat/code/ACE/scripts/research/test_prepare_llm_intervention_campaign_cpu.py:243) fabricates completed call records. Neither passes stdin through `numeric_child` into an entrypoint that reads `.buffer` or returns a nonzero status. Their reported passes therefore do not cover this blocker. No execution was needed to establish the incompatible interfaces.
