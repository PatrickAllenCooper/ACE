Until separately corrected and qualified, require equal complete command-token lengths for every scheduled DPO pair before model loading or any SFT update.** Actual scientific command lengths remain unmeasured; this is a conditional compatibility risk, not an observed scientific failure. ## Safe prospective choices

1. **Retain the current recipe and fail closed on incompatible input.** Future actual-tokenizer qualification should retain every command-plus-EOS sequence and its length. Equal lengths across all eight acquisition commands would suffice for any action/action pair in this proposal; equality with terminal `stop` is unnecessary unless stop participates in a scheduled pair. Regardless, authenticate and check every actual scheduled pair on CPU before any model work. If commands differ, stop for a prospective decision: do not select another hash-ranked pair, discard records, change labels, rename actions, or truncate tokens to pass. Those changes would alter the fixed exposure or representation.
2. **Qualify a new padding-free pair-scoring path.** Score each chosen/rejected completion in its own unpadded forward, then combine scores in original order with autograd intact and take one DPO loss/backward/optimizer step per existing schedule entry. Apply the same declared layout to reference caching, policy scoring, final reference verification and checkpoint reload comparison. Do not detach policy scores or copy the diagnostic's `no_grad` behavior. Batch-shape changes can change floating-point results: retain old qualification and establish new pins/baselines rather than claiming historical bitwise equivalence.
3. **Alternatively qualify an explicitly mask-capable backend/recipe.** This changes the frozen arithmetic and may change memory, speed and determinism. It requires prospective review and measured qualification; silently enabling fallback kernels or deleting masks is not an accepted repair.

## Minimum new qualification

First obtain the already-planned CPU tokenization evidence, including full command lengths—not guessed lengths from names such as `observe_all` or `set_xy`. Add a narrow admission check over the unchanged selected schedule; report all incompatible pairs and preserve them. A finite artificial fixture cannot replace checking every actual prepared scientific record. If all scheduled pairs are equal, this particular padding issue needs no mixed-length engine correction; normal scientific context/resource admission still remains.

If changing execution, limit fabricated checks to unequal lengths in both chosen/rejected orders plus an equal-length control: complete EOS/label handling, ordered scores, both policy gradient contributions, fixed reference, and unchanged one-step exposure. Then separately qualify the revised path on the pinned model/runtime with artificial public inputs: reference creation, DPO forward/backward with checkpoint recomputation, finite gradients and one optimizer update, unchanged reference recheck, and consistent fresh checkpoint reload scoring. Record actual backend, memory, timing and verified GPU work in that future bounded qualification. CPU tokenization or fabricated tests alone cannot establish Flash compatibility.
