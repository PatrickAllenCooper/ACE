# SCM–foundation model viability agenda

Date: 29 September 2026. This is a research agenda with initial gates, not a claim that an FM advantage has been established. No Azure or other closed-model calls are authorized for this agenda.

**Current execution plan:** [research recovery agenda, 1 October 2026](research_recovery_agenda_2026-10-01.md). Its work order and stop gates supersede the dated “next gate” sketches below. Read the [execution ledger](research_execution_2026-09-25.md) for validated outcomes.

## Common contract

Treat a foundation model as an infrequent proposer of a typed, falsifiable object: a mechanism family, module mapping, actuator schema, or hypothesis set. Keep inference, action costs, and grading in numerical code. Use the existing known-graph, fully observed task for comparable mechanism experiments; mark hidden-confounder and partial-identification tasks as different settings. Freeze systems, actions, metrics, and controls before fresh confirmation. Report improvement over the strongest matched *simple* control, not only over an old ACE result. Count every environment sample, intervention, and model call; record seed, source revision, protocol and artifact hashes. Confirm on independent systems and at least one externally selected environment before a broad generalization claim.

The prior portfolio and execution ledger document the failed original ACE comparisons and the results below. The corrected metric and exact query accounting are prerequisites. A positive numerical acquisition result alone is not evidence of a foundation-model contribution.

## Track 1: semantic priors that can be wrong

**Question.** Can an open model supply a compact mechanism-family proposal that improves small-data prediction or intervention choice, while a numerical gate prevents damage when the label is misleading?

**Current evidence (1 October update).** The n16 wrong-proposal screen has MSE .02564, gated .02128, broad .01750: recovery is incomplete. On BoxingGym Lotka, the open-model proposal and a data-only family selector chose the same coupled family with heldout MAE .348. In BoxingGym signal localization, a first-eight/next-eight public-data gate accepted a deliberately wrong source-count proposal on all three development worlds, and a separate equal-strength cue was mixed. Thus syntax and plausibility have been demonstrated; semantic value and safe recovery have not.

**Next gate.** Freeze 24 independent systems in two physical-story families plus anonymous and misleading descriptions. Use the same observed data and learner for typed open-model prior, data-only selector, broad mixture, and oracle-family upper bound. Prespecify a holdout domain and wrong-prior rate. Require lower mean heldout error than the best nonsemantic arm with paired interval excluding zero, and wrong-label performance within 5% of the broad arm. Stop semantic expansion if the data-only selector ties or wrong priors remain harmful. Begin locally with a small proposal cache; use CURC only for the larger numerical matrix. Do not fit a confidence-to-posterior mapping on confirmation systems.

## Track 2: interventions that expose hidden interactions

**Question.** Does posterior-aware pair selection improve mechanism learning after exact action costs, natural-label masks, and a strong fixed schedule are matched?

**Current evidence (1 October update).** Frozen fresh binary-tree systems support the numerical risk-pair selector over fixed factorial hub (.02694 versus .03972 MSE), and a subsequently frozen random-recursive graph family also passes (.02270 versus .05918). Fresh fanout systems do not establish a gain (.01327 versus .01535; paired interval includes zero). All three are synthetic mechanism families, selected in sequence. This is a conditional numerical policy result; a general active-design or foundation-model claim remains premature.

**Next gate.** The existing within-menu fixed factorial, randomized-pair, and single-action comparisons now cover three synthetic topologies. Select an externally authored intervention task or a genuinely different mechanism family **before** scoring; specify its action costs, legal menu, public-data-only selector, fixed varied-value comparator, and heldout forecast target. Run a bounded CPU custody/estimator smoke first. Do not transfer the synthetic risk-policy score unchanged if its Gaussian-linear posterior is misspecified for the new task. Promote beyond these toy SCMs only after a cost-matched fresh task improves heldout feasible-action loss over the strongest same-menu fixed policy. A foundation-model role still requires a separate action-menu proposal comparison.

## Track 3: modular memory and sparse repair

**Question.** Can a library reuse unchanged local mechanisms while identifying and repairing the few changed ones under distribution shift?

**Current evidence (1 October update).** On an easy one-change task, the changed node was almost always found, and numerical mixture often tied adaptive scratch. In connected three-change systems, a four-response assay found 23/36 changed motifs in its top four; unchanged descendants were false positives after upstream shift. The 12-system out-of-bank development study failed its acquisition gate: source64 risk-pair warm changed-motif MSE .10965 versus fixed .10716. An RBF residual helps the known failed motif, but the node-agnostic CV gate and a support-taper variant still harm some unchanged motifs. The numerical protection rule is not ready for neural scale-up.

**Next gate.** Redesign the repair decision on saved acquired data, separating conditional-mean model mismatch from lack of local support. Compare source warm start, numerical retrieval mixture, scratch, and a conservative repair or abstention rule on identical trajectories; keep an untouched-motif protection metric. Freeze a new connected-system set only after the rule stops harming unchanged motifs in development. Require at least 2× fewer target trajectories than the best scratch/retrieval control with no supported >5% unchanged-module degradation before a GPU architecture scale-up. Descriptor-guided retrieval is a separate semantic ablation. Use CPU development first.

## Track 4: action-language compiler

**Question.** Can an open model translate natural intervention constraints into a *validated* actuator menu that increases useful reachable experiments?

**Current evidence (1 October update).** The numerical joint-action code, cost/mask ledger, and deterministic menu validator work. A hand-written parser scored 8/8 on an in-sample fixture and 0/8 on a later-authored temporal-constraint stress set. This exposes parser brittleness; it is not independent evidence that an open model improves compilation. No language-to-menu advantage has been measured.

**Next gate.** Obtain independently authored constraint descriptions after freezing both the rule-parser baseline and an open-model prompt. Use the existing formal schemas and deterministic validator to compare exact legal-menu recall, invalid proposal rate, reachable information gain, and downstream heldout mechanism loss at matched cost. The language must contain the needed constraints; the answer must not be leaked through exemplars. Keep the 8/8 and 0/8 hand-written fixtures as development diagnostics only. A CPU-only fixture and scorer audit should precede any small offline open-model GPU canary; no model run is justified by the existing in-sample parser results alone.

## Track 5: partial identification and belief revision

**Question.** Can an open model distinguish what observations identify from what requires an intervention, and update a familiar prior locally after contradictory evidence?

**Current evidence (1 October update).** The exact finite gate and a 20-task suite establish a gradable task with informative and null menus; a public-text arithmetic rule control scores 20/20. An offline Qwen2.5-1.5B-Instruct four-task canary produced eight responses, all invalid under the frozen JSON schema. Diagnostic object extraction found 0/4 correct actions and four false claims of observational identification. This negative direct-prompt development result blocks expansion with the same model/prompt; it does not test a tool-assisted architecture or a broader model class.

**Next gate.** Keep the 20-task suite and exact-rule baseline fixed. Design a typed proposal interface in which a model suggests candidate hypotheses or queries and an exact tool checks observational equivalence, legal actions, and posterior updates. First verify interface and refusal behavior on CPU using deliberately malformed and misleading proposals. A new offline open-model canary needs a frozen prompt and balanced informative/noninformative tasks, and should run only if the interface provides a testable benefit beyond deterministic enumeration. Score coverage, calibration/log score, action value, false certainty, and repair locality. Do not treat the failed direct-prompt canary as evidence that a tool-assisted interface works.

## Order and resource gates

First complete exact Track 5 and a Track 4 validator smoke test locally, while analyzing existing Tracks 1–3 artifacts. Then run one small, frozen independent development batch per track. Use CURC for CPU matrices that materially exceed local cost and for a modular GPU prototype only after its numerical gate. The user is willing to leave jobs queued; queue delay alone is not a reason to alter another project's jobs or submit duplicate ACE jobs. No Azure or other closed-source calls. Record proposed caps and actual usage in the execution ledger. Select an external environment *before* scoring; BoxingGym is one candidate, with repository revision and task pinned.

## Related work boundary

LLM-SR already proposes equations as programs. Model Discovery Agent already combines model proposals, Bayesian inference, and value-of-information design. BoxingGym already evaluates experiment design and model discovery. Independent causal mechanisms are established prior art. The distinctive tests here are robustly *wrong* semantic priors, validated action compilation under constraints, local repair under connected covariate shift, and calibrated refusal where interventional effects are not identified. These are hypotheses for comparative study, not novelty claims before a focused literature review.
