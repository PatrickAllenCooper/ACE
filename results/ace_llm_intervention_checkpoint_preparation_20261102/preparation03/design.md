# Checkpointed artificial runtime qualification

GPU08 established exact equality in its eight canonical scoring comparisons, then exhausted the 20 GB slice. Its first 4,341-token supervised update completed at 16,565,905,920 peak allocated bytes. The following 7,343-token forward failed before its backward pass. All inputs, the one completed update and the failure remain preserved. This is runtime evidence, not an intervention-efficiency result.

The next candidate recomputes decoder activations during backward rather than retaining them all. It keeps the same 20 GB slice, model, input sequences, masks, objectives, optimizer and six-step artificial schedule. It does not shorten inputs or increase GPU memory. PyTorch's [2.9 checkpoint documentation](https://docs.pytorch.org/docs/2.9/checkpoint.html) recommends explicit non-reentrant checkpointing and warns that recomputation must agree with the original forward. The new wrapper preserves RNG state, checks captured decoder mode and reference flags before recomputation, and rejects caches. It works during eval-mode scoring, where native training-mode checkpoint switches would not suffice.

Before optimization, eight new captures compare canonical selected scoring with checkpointing off and on for supervised and preference losses, with two repeats each. The previous full-versus-selected test is retained as GPU08 evidence. It is not repeated. Original loss and gradient tolerances remain fixed. Exact same-path repeatability is required. Every capture and comparison is saved before the gate rejects a failure.

The candidate then runs the original 4,341/7,343/7,343-token schedule for three SFT and three DPO updates. Every backward must record at least 28 decoder recomputations before its optimizer step. The DPO reference is frozen separately. All frozen base and projection signatures must remain equal, reference scores must remain equal, and a newly saved adapter must reload into a fresh base with identical scores. Four legal generations must complete, including an identical repeated state. No generated command is executed and no scientific world or environment response is created.

Three new artificial methods check parameter gradients with frozen inputs, an independent finite-difference oracle, unchanged state, recomputation counts, mode/reference mutation rejection, no-grad bypass and invalid layouts/cache use. These do not qualify the real model or its longer contexts. The new source requires independent review, an exclusive source/input/resource freeze and actual-runtime execution before acceptance.

Proposed resource cap is one A100 20 GB slice, four requested CPUs with at most eight allocated, 12 GiB host memory and ten minutes. The failure supplies measured memory justification for recomputation. Expected savings are not yet measured. Startup, progress, worker and supervisor deadlines, independent owned-process GPU telemetry and cleanup guards remain enforced. CPU preparation stays outside the GPU allocation. Conservative reservations would rise from 49,200 to 54,000 CPU-seconds and from 5,100 to 5,700 GPU-seconds within the existing 57,600/7,200 ceiling. No production allocation follows automatically.

A successful artificial qualification permits use of this exact computation recipe in a separately frozen study. It does not permit reusing artificial adapters as scientific initialization. Scientific policy training must start from the pinned pristine base and fresh adapters, preserve independent training/development/confirmation namespaces and report all costs and failures.
