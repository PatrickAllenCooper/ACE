# Fresh factorial-pair confirmation (29 September 2026)

The [protocol](../../docs/development/guidance/protocol_connected_factorial_pair_confirmation_2026-09-29.json) and runner were frozen at `5fde2a2e9e4e6478249d7549a098f5991f1bd527` before generating systems 900–939. All systems have 30 nodes, ten connected motifs in a binary tree, root SD 0.15, intervention penalty 4, and a 400-unit cost cap. The primary comparison is posterior-risk pair acquisition versus a fixed factorial pair control that covers all four actuator-value combinations at the upstream motif. Each pair arm used five 8-response actions and spent 360 units. The fixed design used four actions on motif 0 and one on motif 1; risk could select motif and values from the same menu.

The prespecified primary gate **passes** on the 40 fresh systems. Final feasible-motif MSE was 0.026942 for risk pair and 0.039722 for the factorial control, giving a ratio of means of 0.6783. The mean paired difference (risk minus factorial) was −0.012780 with a two-sided 95% paired-t interval [−0.020726, −0.004834]. Risk won 26 of 40 systems. The protocol required a ratio below 0.80 and the interval upper endpoint below zero. Both conditions pass.

For context, mean feasible MSE was 0.055295 for coverage pair, 0.030930 for balanced-risk pair, 0.043983 for hub-coverage pair, and 0.047356 for hub-random pair. Among fixed pair controls, factorial was strongest. Coverage single was 0.055522 and random single 0.085990. Random pair was 0.215677. These are contextual arms; their comparisons do not alter the primary gate.

The result supports an adaptive **pair-policy** advantage within this exact synthetic graph family, action menu, learner, and cost model. It does not separately identify whether choosing the motif, choosing the value combination, or concentrating actions caused the advantage. It does not show a foundation-model benefit. The earlier joint-versus-single confirmation gate remains failed. Follow-up should test a policy that matches risk's motif visits while using a fixed value schedule, and a broader family with different interaction strengths and topology, before a general B claim.

The run produced 40 system receipts, 360 arm rows, and 17,600 synthetic arm-response counts (pair arms 40 each, single arms 80 each). Every action log, metric file, and system specification is archived with SHA-256 hashes. The runner checked all nine arms' sample and actuator costs, action counts, and the factorial value schedule. An independent full rerun produced byte-identical files, including the analysis and receipts. All work was local numerical simulation; no CURC job or closed-model call was used.
