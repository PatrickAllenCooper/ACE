# Training-only, node-agnostic residual repair: development result

Post hoc development on the 12 previously scored connected systems, using only their **saved** acquired data. Source revision `09fd1dbd`. Every motif receives the same candidate RBF residual model. Four-fold acquired-label CV chooses width and precision; the residual is activated only if it beats the source-warm linear model by at least 10% and 0.0025 absolute CV MSE. The sealed feasible-action panel is used only for final scoring. This gate was fixed in code before these node-wide outcomes were generated, but the systems and RBF family had already informed the prior motif-7 capacity screen. This is development, not independent confirmation.

Across 480 motif × source-size × policy cells, the gate selected 65 repairs. It selected the out-of-bank motif 7 in **48/48** cells, while selecting 11 of 336 unchanged-motif cells. On the source-16 risk-policy arm, mean all-motif MSE fell .04068→.01813 and changed-motif MSE .11446→.03900, with unchanged mean .00906→.00919. These are reused-system point estimates.

The gate **fails as a safe repair method**. On the source-64 risk-policy arm, all-motif mean error rose .03708→.06251 and changed-motif mean .10965→.19426. The worst case is seed 2007 motif 0: acquired-label CV favored the RBF (0.02264 versus 0.02624), but feasible-panel MSE jumped **0.01427→2.34842**. The RBF was selected for motif 0 in 4/12 source-64 risk cells. Cross-validation on acquired contexts did not protect against extrapolation to feasible but poorly covered parent contexts. On the source-16 fixed arm, unchanged mean rose .01016→.01211; on source-64 fixed, .00681→.00855. These degradations also violate a simple unchanged-module protection story.

All 480 source-warm linear scores match the frozen parent run within 1e-10. The metrics CSV is byte-identical on independent replay (SHA-256 `68d2ba3d0069c3ef73fc636b93f6fa681dc6c86ddfc22f20888240ea00b272a0`); the input suite and output hashes are in `complete.json`. No new training queries, CURC job, closed-model call, or non-ACE job was used. CURC SSH remained disconnected.

Next development question: can a **training-only** support or disagreement criterion suppress residual models when the feasible-action context distribution lies outside the acquired training support? That criterion must be frozen before fresh systems and compared with simply using the source-warm linear model. Do not launch confirmation or neural scaling from this gate.
