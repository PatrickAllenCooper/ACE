# Counted adaptive transfer-allocation development check

This diagnostic reuses the 12 development systems, both change types, and k∈{1,3,10} from the protected-transfer screen. It tests a different way to spend the **same 200 target examples**: acquire four examples at each of 30 nodes (120), rank nodes by early source-versus-old marginal evidence, then spend the remaining 80 on positively nominated nodes first, cycling through them up to 14 examples per node. Any remaining budget goes to other nodes. Nomination and allocation see only acquired examples; changed-node labels and the held-out test panel are used only for scoring. The source library still costs 2,560 separate pretraining examples. The baseline fits the old-centered posterior on this adaptive data; the candidate may switch to a source-centered posterior only after a counted conditional Bayes factor exceeds odds 4.

All 72 settings spend exactly 200 target examples; `node_metrics.csv` records 2,160 node-level decisions and errors. Against **adaptive warm start on the same acquired data**, the switched model's changed-node MSE ratios for family changes are **0.985, 0.425, 0.852** at k=1,3,10. Untouched ratios are 1.000 in every setting; coefficient-change changed-node ratios are 1.025, 1.000, 1.000. The written development gate requires every family ratio ≤0.8, so the switch **still fails** at k=1 and k=10. Do not promote the source-switch architecture or launch fresh confirmation on this rule.

The allocation policy itself is more informative. Compared with the archived **uniform-allocation warm start** at the same 200-example budget, adaptive warm start changes family-change changed-node MSE by ratios **0.220, 0.155, 0.634** for k=1,3,10. Yet untouched-node ratios are 1.006, 1.040, **1.099**: concentrating examples on nominees can harm unchanged mechanisms when many nodes change. For coefficient changes, changed-node ratios are 1.016, 0.860, 1.000, with little benefit from source nomination. This is a development clue for an acquisition method that allocates a guaranteed floor to all mechanisms, not a transfer result or a fresh scientific claim. `summary.csv` contains every ratio, nomination count, switch count, and mean sample allocation.

The [script](../../scripts/research/transfer_adaptive_prequential_dev.py) reconstructs the fixed source library and target data, compares to the archived uniform warm node errors by exact setting/node keys, and saves a SHA-256 receipt for all outputs and the reference data. This is local numerical work; no CURC job or closed-source model call was needed.
