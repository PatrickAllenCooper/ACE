# Held-out transfer allocation audit (29 September 2026)

This is an evaluation-only audit of the [fresh held-out-form experiment](../local_transfer_heldout_form_fresh_20260929/README.md), using its 20 systems and `heldout_tanh` setting. It made no new simulator query or model call. The script checked the 40 input cell receipts and action, system, and metric hashes, then decomposed the unchanged-node error by adaptive response count. A second run produced byte-identical `per_node.csv`, `summary.csv`, and receipt.

With **16 source responses per node**, the top-eight policy leaves 22 unchanged nodes per system with four target responses; their adaptive soft-mixture MSE is **1.3276×** the uniform control, contributing **+1.4080** summed squared error across 440 node-system instances. Seven unchanged nodes per system receive 14 target responses and improve to **0.6665×** uniform, contributing **−0.5059** across 140 instances. The net unchanged error is **+0.9021**, yielding the original **1.1551×** overall ratio. With 64 source responses the corresponding low-count ratio is 1.0409 and the net unchanged ratio is 1.0040. On unchanged nodes, the adaptive soft mixture and source-warm fits have equal MSE to displayed precision; the immediate harm is the allocation of scarce target responses, not a large mixture switch on those nodes.

The changed node was ranked first by the four-response evidence assay in all 20 systems at both source sizes. This is an unusually easy change-localization benchmark, so it is a poor basis for claiming a general detector. It does suggest a next *prospectively frozen* controller: give all 30 nodes six responses (180), then spend the remaining 20 as five extra responses on each of the top four evidence-ranked nodes. This would avoid four-response untouched nodes while retaining some targeted acquisition. The current data were used to choose that schedule; any comparison here would be post hoc development only. A new system set and a harder change-localization family are needed before promotion.

Files: `per_node.csv` has 1,200 node-system-source rows; `summary.csv` has eight group summaries; `complete.json` records the parent suite hash and output hashes. No CURC job was needed.
