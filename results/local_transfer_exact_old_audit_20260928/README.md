# Exact-old-mechanism transfer audit

The [evaluation-only audit](../../scripts/research/audit_transfer_exact_old.py), source revision `81b7974e4a673c24f11a98702d331885d673a1e4`, reconstructs the 12 archived development seeds, two change types, and k∈{1,3,10}, then verifies the existing floor-six and uniform-warm node files by input hash. It reads hidden coefficient truth **only to diagnose the benchmark**; these quantities are not supplied to an acquisition or transfer policy. There are no new oracle queries, jobs, or model calls.

Across 72 settings and 2,160 node instances, the old source coefficient vector is **bitwise identical** to the target truth for all **1,824 unchanged nodes**. None of the 336 changed nodes has that equality. Thus the unadapted old predictor has exactly zero mechanism error on every unchanged node in this synthetic generator. Updating an unchanged node with noisy target examples can introduce error. This is a deliberate idealized sparse-change construction, but it is too favorable to treat as evidence that a learned source module is safely reusable without estimation error.

For the family-change k=10 floor-six experiment, all 240 untouched node instances receive six target examples and none is nominated for a switch. The 78 instances that also receive six examples under uniform allocation have matching summed error (ratio 1.000000 within floating precision). The other 162 receive seven under uniform allocation; their floor-six versus uniform error ratio is **1.0939**. All of the previously reported aggregate 1.063 untouched-node harm comes from those one-example shortfalls, with no false module switch in this group. The result is an allocation effect atop an exact-old benchmark, not evidence of unsafe source-family replacement on untouched nodes.

The [next benchmark design](../../docs/development/guidance/transfer_finite_source_plan_2026-09-28.md) estimates old modules from finite, counted source data while retaining shared latent truth for unchanged mechanisms. Existing exact-old experiments remain valid for their stated idealized setting. They do not establish performance with learned, uncertain source modules.
